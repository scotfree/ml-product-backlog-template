# Iterate — improve one thing per run

## Description

_Change one variable at a time. Track what helped._

## Upstream / Downstream contract

_Analysis needs to know what changed between runs to attribute improvements._

## Definition of Done

- _A short log (one line per run) of what you changed and what happened._
- _Stop when improvements level off or the sprint ends._

## Demo

_Show the run log; call out the best change so far and one thing that didn't help._

## Subtasks

- _One issue per experimental direction._
- _Data changes, hyperparameter changes, and architecture changes should be separate runs, not combined._

## Estimate

_Rough size — minutes, hours, or days. If it's more than a few days, break it up._
