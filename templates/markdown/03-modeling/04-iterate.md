# Iterate — improve one thing per run

_Change one variable at a time. Track what helped._

- **Upstream/downstream:** _Analysis needs to know what changed between runs to attribute improvements._
- **Definition of done:** _A short log (one line per run) of what you changed and what happened. Stop when improvements level off or the sprint ends._
- **Demo:** _Show the run log; call out the best change so far and one thing that didn't help._
- **Subtasks:**
  - _One issue per experimental direction._
  - _Data changes, hyperparameter changes, and architecture changes should be separate runs, not combined._
